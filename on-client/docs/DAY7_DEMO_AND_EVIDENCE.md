## 2. 고른 핵심 기능 3개

### 핵심 기능 1 — 계정·기기·세션 상태

- 제공된 부분: `public/index.html`과 `public/app.js`의 기본 화면·조회 흐름 및 서버 응답 처리.
- 내가 직접 구현·개선한 부분: `student/extension.mjs`의 `renderIdentity` 표시 함수. 연결 모드와 예제 자료를 구분하고, 누락·잘못된 응답은 확인 불가로 표시하도록 구성했습니다.
- 실제 확인 결과: **미확인.** 최신 버전에서 화면을 열어 계정·기기·세션 각각의 상태와 출처를 시연한 결과는 아직 이 기록에 없습니다.
- 잘못된 입력이나 연결 실패 때의 동작: 코드에는 누락된 값, 잘못된 목록 형식, 요청 실패 및 unknown을 확인 불가로 표시하는 처리가 있습니다. 최신 화면에서 각 경우를 직접 재현한 결과는 미확인입니다.
- 근거(상대 경로): `on-client/public/index.html`, `on-client/public/app.js`, `on-client/student/extension.mjs`의 `renderIdentity`.

### 핵심 기능 2 — 업무 앱 접근 판정

- 제공된 부분: `public/app.js`의 업무 앱 화면과 접근 판정 요청 흐름.
- 내가 직접 구현·개선한 부분: `student/extension.mjs`의 `renderDecision` 표시 함수. 허용·거부·추가 확인 필요 상태, 판정 이유·시각, 연결 모드 및 확인 불가 안내를 표시합니다.
- 실제 확인 결과: **미확인.** 실제 SDP/운영 엔진에서 허용과 거부를 각각 확인한 로그는 없습니다. 예제 모드에서의 화면 시연은 운영 판정 성공의 증거가 아닙니다.
- 잘못된 입력이나 연결 실패 때의 동작: 코드상 알 수 없는 판정이나 검증되지 않은 응답은 허용으로 취급하지 않습니다. 오류 상황별 최신 화면 재현은 미확인입니다.
- 근거(상대 경로): `on-client/public/app.js`, `on-client/student/extension.mjs`의 `renderDecision`, `on-client/src/server.mjs`.

### 핵심 기능 3 — 보안 기록 타임라인

- 제공된 부분: `public/app.js`의 기록 조회·API 응답 처리 및 기본 기록 화면 흐름.
- 내가 직접 구현·개선한 부분: `student/extension.mjs`의 `renderEvents`. 기록 시각 기준 최신순 정렬, 기록 종류·업무 앱·접속 상태 필터, 상세 기록의 근거·규칙·상태 표시, 한국 시각 병기 및 예제·미연결·확인 불가 안내가 코드에 있습니다.
- 실제 확인 결과: **부분 확인.** `npm run check`는 통과했고 관련 코드는 저장소에서 확인했습니다. 다만 최신 패키지에서 필터 세 가지를 직접 조작하는 장면을 재현한 기록은 아직 없어 UI 동작 자체는 미확인입니다.
- 잘못된 입력이나 연결 실패 때의 동작: 코드상 조회 실패 또는 계약 불일치 시 이전 기록을 성공 결과인 것처럼 표시하지 않습니다. 실제 연결 실패 재현 화면은 미확인입니다.
- 근거(상대 경로): `on-client/student/extension.mjs`의 `renderEvents`, `on-client/public/app.js`의 `renderEvents`, `on-client/src/server.mjs`의 기록 응답 검증.

## 3. 값의 종류 구분

| 종류 | 기록 방법과 현재 상태 |
|---|---|
| 실제 조회 | 본인 PC의 CPU·메모리·디스크 또는 실제 서비스 API에서 정상 응답을 얻은 값만 기록합니다. 출처와 조회 시각이 필요합니다. **이 기록에는 실측 수치와 캡처가 아직 없습니다.** |
| 설명용 예시 | `demo` 모드의 데이터. 화면 설명용이며 실제 PC나 운영 서비스의 결과가 아닙니다. 실제 조회값과 섞지 않습니다. |
| 미연결 | 기본 실행의 엔진 상태 `disconnected` 등 실제 서비스에서 조회하지 못한 항목. 빈 목록이나 정상 상태로 바꾸지 않습니다. |
| 확인 불가 | `unknown`, 오류, 응답 형식 불일치, 측정 실패 등. 정상 또는 안전하다는 뜻이 아닙니다. 이유와 시각이 확인되면 함께 기록합니다. |

- 메모리 사용량: 미확인 — 화면에서 다시 측정하고 값·단위·측정 시각·출처를 기록합니다.
- 시스템 드라이브 남은 공간: 미확인 — 화면에서 다시 측정하고 값·단위·측정 시각·출처를 기록합니다.
- 실제 SDP 기록/API 응답: 미확인 — 승인된 운영 설정으로 조회가 성공하기 전에는 실제 결과라고 쓰지 않습니다.
- 화면 캡처: 미확인 — 시연 후 개인정보를 가린 캡처를 확보합니다.

- 최종 소스 커밋: 미확인 — 최종 문서 반영 후 저장소에서 `git rev-parse HEAD`로 확인하고, GitHub 브랜치에도 같은 커밋이 있는지 확인합니다.

### 재현 명령 (Git Bash)

저장소에서 최신 브랜치를 받은 뒤 앱 폴더로 이동해 실행합니다. 기존 패키지와 제출물을 유지하려면 아래 출력 이름처럼 새 경로를 사용합니다.

```bash
cd ~/AppData/Local/ALEPH/Workbench/projects/밍밍전 || exit 1
git pull --ff-only origin finish/timeline-package-app || exit 1
cd on-client || exit 1
npm run check || exit 1
npm run demo
```

`npm run demo`는 **화면 연습 전용 예제 모드**입니다. 실제 SDP 연결, 실제 직원 기록 또는 운영 기능 성공을 증명하지 않습니다. 화면에서 계정 상태 → 업무 앱 접근 판정 → 보안 기록 타임라인 순으로 시연하고, 타임라인의 기록 종류·업무 앱·접속 상태 필터를 하나씩 바꿉니다. 서버는 사용 중인 PowerShell/Git Bash 창에서 `Ctrl+C`로 종료합니다.

시연 후 별도 포장을 만들려면 `on-client`에서 다음과 같이 새 경로를 사용합니다. 아래 명령은 패키지 생성만 하며 승인된 운영 바로가기를 만들지는 않습니다.

```bash
npm run package-app -- --source . --out "$USERPROFILE/Desktop/밍밍-7일차-시연패키지"
```

위 경로의 `<사용자>`는 설명용 자리표시자입니다. 실제 PC에서 사용할 경로로 바꾸고, 출력 폴더와 같은 이름의 ZIP이 없는지 먼저 확인합니다. 실행 후 매니페스트의 `source.commit`과 `git rev-parse HEAD`가 같은지 확인하고, ZIP 무결성 검사와 아이콘 확인을 다시 합니다. 소스가 수정된 뒤에는 기존 패키지를 최종 패키지라고 부르지 않습니다.

## 8. 남은 한계와 다음에 확인할 것

### 아직 안 되거나 확인 불가로 남은 것

1. 승인된 운영 호스트 런타임·바로가기 등록 방식과 운영 앱 승인 키 검증이 확인되지 않았습니다. 패키지에는 승인된 바로가기가 없습니다.
2. 실제 SDP 서버에서 계정·기기·세션·접근 판정·보안 기록이 성공적으로 조회된 근거가 없습니다.
3. 실제 AI 게이트웨이 호출, 실제 운영 XDR 기록, 외부 OSV 조회 결과는 이번 기록에서 검증하지 않았습니다.
4. CPU·메모리·디스크 실측값과 화면 캡처가 아직 이 문서에 첨부되지 않았습니다.
5. 최신 소스와 기존 6일차 패키지가 같은 커밋에서 생성되지 않았습니다. 최종 문서가 반영된 뒤 새 경로로 패키징하고 매니페스트 커밋을 비교해야 합니다.
6. 타임라인의 세 필터와 상세 보기, 실패 상황 표시를 새로 만든 최종 빌드에서 직접 시연한 기록이 없습니다.
7. 다른 사람의 첫 사용 관찰과 보완 후 재시험은 실시하지 않았습니다.

- [ ] 최신 소스에서 `npm run check` 통과 확인.
- [ ] `npm run demo`로 계정 상태 → 접근 판정 → 타임라인 순서로 한 번 연습.
- [ ] 기록 종류·업무 앱·접속 상태 필터와 상세 근거 표시를 직접 조작해 확인.
- [ ] 내 PC 상태의 CPU·메모리·디스크를 측정해 실제 화면값·출처·측정 시각을 개인정보 없이 기록.
- [ ] 제공 예제(demo), 연결 없음(disconnected), 확인 불가(unknown)를 서로 다른 상태로 시연.

- [ ] 운영자에게 승인된 런타임·바로가기 설치 절차·운영 앱 승인 키 검증 방법을 문의. 키와 설정 내용 자체는 문서에 기록하지 않음.
- [ ] 다른 사용자의 첫 사용 관찰을 실제로 했다면 그때만 막힌 위치와 재시험 결과를 기록.
