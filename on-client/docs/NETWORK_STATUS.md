# 네트워크·방화벽·Windows 기록

## 목적 및 기존 기능과의 구분

- 기존 기능은 CPU·메모리·디스크를 별도 API로 실측합니다. 이 문서의 네트워크·방화벽·Windows 이벤트 조회는 그 결과와 분리되어 있습니다.
- 새 API `GET /api/network-status`는 사용자가 「지금 조회」를 눌렀을 때만 로컬 Windows에서 조회합니다.
- SDP 상태는 실제 SDP 원천에 대한 본인 identity 조회가 성공했을 때만 `SDP 연결 확인`으로 표시합니다. 연결 설정이 없으면 `SDP 미연결`, 설정은 있으나 원천 조회 성공을 증명하지 못하면 `확인 불가`입니다. PC 네트워크 조회 성공만으로 SDP 연결을 추정하지 않습니다.
- SDP 연결 확인은 원천의 본인 identity 조회만 수행합니다. 로컬 네트워크 구성·방화벽 설정·Windows 이벤트 건수는 SDP 서버로 보내지 않습니다.

## 읽기 전용 데이터 출처

- 네트워크 구성: Windows PowerShell `Get-NetIPConfiguration -All`로 인터페이스 이름·연결 상태·IPv4/IPv6·기본 게이트웨이·DNS·네트워크 범주/연결 상태를 읽습니다.
- 방화벽: `Get-NetFirewallProfile -PolicyStore ActiveStore`의 도메인/개인/공용 프로필, 활성화 여부, 기본 인바운드/아웃바운드 동작을 읽습니다.
- 이벤트 로그: `Get-WinEvent`로 System과 Application의 최근 24시간 Level 2(Error), Level 3(Warning) 이벤트 개수를 각각 집계합니다. 이벤트 원문은 수집·표시하지 않습니다.
- 모든 명령은 고정된 스크립트이며 브라우저 입력으로 명령을 만들지 않습니다. 조회 실패는 항목별 `확인 불가`와 이유로 표시합니다. 관리자 권한을 자동으로 올리거나 요청하지 않습니다.

## 해석상의 한계와 안전

- Windows 이벤트 경고/오류 건수는 기록 개수입니다. 이를 침해·공격 탐지, 감염 판정, 공격 징후 확정으로 해석하지 않습니다. 이벤트 로그의 권한이나 상태에 따라 읽을 수 없을 수 있습니다.
- 방화벽 조회는 현재 유효 프로필의 설정을 읽을 뿐 규칙 전체를 평가하지 않습니다. 이 기능은 방화벽을 켜거나 끄고, 규칙을 수정하거나 네트워크 설정을 바꾸지 않습니다.
- 이 기능에는 공격·침투를 재현하는 시험이 없습니다.
- 최근 조회 타임라인은 브라우저 메모리에 최근 10회만 유지합니다. 새로고침/재접속 시 초기화되고 디스크나 외부 서버로 전송하지 않습니다.
- IP 주소, 게이트웨이, DNS는 현재 PC의 실제 네트워크 정보이므로 화면/스크린샷을 공유할 때 민감 정보인지 확인하세요.

## 실행 및 검증

프로젝트 루트의 Git Bash에서:

```bash
cd on-client
npm run check
npm start
```

화면에서 「지금 조회」를 눌러 다음을 확인합니다.

1. 네트워크 인터페이스/IP/게이트웨이/DNS에 측정 시각과 출처가 표시됩니다.
2. 도메인·개인·공용 방화벽 프로필 조회는 읽기만 합니다.
3. System·Application 로그의 최근 24시간 경고/오류 건수가 각각 표시되며, 조회할 수 없는 로그는 0건으로 위장하지 않습니다.
4. SDP 상태는 PC 조회와 별도이며, 실제 원천 조회 성공/미연결/확인 불가가 구분됩니다.
5. 두 번 이상 조회해 타임라인 최신순 정렬과 종류별 필터를 확인합니다.
6. 페이지 새로고침 후 기록이 초기화되는지 확인합니다.

패키지는 작업 트리가 깨끗한 커밋 상태에서 생성합니다. 변경을 검토하고 커밋한 뒤 `npm run package-app`을 실행해 ZIP, 매니페스트, 바탕화면 바로가기를 생성하고 바로가기로 다시 실행합니다.
