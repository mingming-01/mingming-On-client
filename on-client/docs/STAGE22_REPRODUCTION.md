## 4. 데이터 보존·백업·복원 계획

- 기존 `밍밍전` 폴더는 재현용으로 덮어쓰지 않고 보존한다.
- 재현용 코드는 원격 저장소를 별도 폴더에 복제하고 기록된 커밋으로 고정한다. Git은 추적 대상 코드·문서의 복원 기준이며 비추적 파일, 개인 설정, 외부 시스템 데이터까지 백업하지 않는다.
- 인증·운영 설정은 기존 폴더에서 무작정 복사하지 않는다. 필요한 설정은 담당자가 승인한 절차로 별도 관리하며 토큰·비밀번호·API 키를 문서나 커밋에 기록하지 않는다.
- 이번 재현에서 데이터베이스 백업·복원이나 외부 시스템 데이터 복구를 실행하지 않았다. 이 기능들의 복원은 미검증이며 지원을 보장하지 않는다.
- 복원 계획의 범위는 기록된 커밋의 코드·문서 재체크아웃에 한정된다. 운영 데이터와 비밀 설정에는 별도 승인된 백업·복원 절차가 필요하다.

## 5. 지원 범위와 최종 제출 상태

- 직접 확인: 새 폴더 복제, 지정 커밋 고정, Node/npm 버전, 문법 검사, 데모 화면, 일반 실행의 연결 없음 화면, 재실행.
- 미확인: 실제 접근 제어/XDR 연결, 실제 AI 연결·사건 설명, 실제 OSV 조회, 공식 22단계 제출 및 AI 원문 판정.
- 19단계 실제 보안 조치 집행은 준비되지 않았으며 미완료다.
- 데모 결과는 실제 연결 결과가 아니다. `ENGINE_NOT_CONNECTED`는 연결 실패 상태로 기록하며 성공으로 바꾸지 않는다.
- 이 문서는 공식 제출 완료나 통과를 뜻하지 않는다. 원문 전달 완료와 AI 검토 통과는 별개다.
- 이 기록의 실행 증거는 소스 기준 커밋 `f03f7d4244e2ddbac4eb27785444b2ab4e520576`에 대한 것이다. 이 문서를 추가하는 문서 커밋 자체에서 애플리케이션을 다시 실행했다고 간주하지 않는다. 제출 시 과제 화면에서 실제 최종 저장소 주소와 40자리 커밋을 다시 확인한다.
